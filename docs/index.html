Timely Guidance for Fast Decisions: Dynamic LLM–Jev Collaboration under Time Pressure

Keeping unfinished slow reasoning useful for fast decisions as the environment changes.

In brief

Agents must act within limited decision windows while the state underlying slow reasoning continues to change. DynaJev combines an LLM planner with Jev, a System One model for fast, structured decisions. Handoffs adapt the visible reasoning prefix to the latest observation, and post-execution feedback controls whether slow reasoning continues or restarts. Offline, collaboration trajectories provide role-specific skills for planning and action selection with frozen model weights.

Challenge 01

Ambiguous action cues

Partial reasoning may contain tentative alternatives without a clear recommendation for the current move.

→

Improvement

Current action guidance

Structured handoffs turn available reasoning into action recommendations, targets, short routes, and risks.

Challenge 02

Stale reasoning

Guidance can become outdated as actions change the environment while the planner continues from an earlier observation.

→

Improvement

Updated guidance and selective restarts

The formatter retains applicable guidance, revises outdated details, and marks uncertainty; feedback restarts the planner when its planning basis no longer applies.

Challenge 03

Late useful guidance

Waiting for completed reasoning can miss the decision window.

→

Improvement

Act before reasoning completes

Jev uses the currently visible prefix and handoff to select an action within the shared budget.

Across the evaluation

DynaJev achieves the highest or joint-highest Snake scores across the evaluated difficulties and competitive performance in additional tasks.

03 / Method

How DynaJev keeps reasoning useful

Update the guidance for the current state, and restart slow reasoning when its planning basis no longer applies.

01

LLM Planner

Develops slow reasoning across decision windows. Only the released prefix is available to downstream modules.

02

LLM Formatter

Combines the visible prefix with the latest observation to produce structured guidance for the current state.

03

Jev Actor

Selects the current action using the latest observation, the handoff, and the visible prefix.

04

Jev Feedback

Checks the planning basis after execution and requests a restart when changes such as an invalid target or newly blocked route undermine it. Ordinary movement or elapsed steps alone need not trigger a restart.

Two model backbones, four prompt roles.

Task-specific guidance

A Snake handoff can organize four kinds of information.

SAFEImmediate action recommendations and notes
TARGETThe current target and relevant timing
ROUTEAn advisory short continuation
RISKSHazards and unresolved uncertainty

The route is advisory. Jev reselects each action using the latest observation.

Current observations take precedence when they conflict with slow guidance. Updating the handoff does not rewrite the ongoing planner response.

2,048

Evaluation clock

Each step has a shared allowance of 2,048 output tokens covering all online modules. A slow planning round can span steps, with a cap of 12,288 tokens. The clock tracks simulated output-token progress rather than measured wall-clock latency. Video playback time does not represent model inference time.

Simulation protocol

The simulator precomputes each slow response and progressively exposes its budgeted prefixes. Each decision cycle advances the environment once. Newly released planner tokens and other online outputs are charged to the shared allowance; reusing an already released prefix is not charged again. Input tokens and offline refinement calls are excluded. All online roles use the same visible prefix snapshot within a cycle, and tokens disclosed after that snapshot become available in the next cycle.

Offline skill refinement

An offline LLM induces and revises a reusable skillbook from training trajectories, then compiles it into role-specific instructions for the planner and actor. Training task success helps assess and select revisions. Each collaboration configuration uses its own skillbook, learned on training settings disjoint from testing and fixed before evaluation. The formatter and checker retain their base instructions; all model weights remain frozen.

Skillbooks are refined on six additional Snake-Hard training seeds, disjoint from the test seeds. Training success requires survival to step 30 and at least one collected food item. Jev-only uses skills only for its actor.

05 / Analysis

What the comparisons reveal

01

The interface changes the value of continuing reasoning

On Snake-Hard without skills, Per-Step outperforms Completion with the Prefix interface, but the ordering reverses with Handoff. This suggests that the value of continued reasoning depends on how accumulated analysis is adapted to the current state. Updating guidance need not require restarting the planner at every step.

Handoff both structures partial reasoning and adapts it to the latest observation; these comparisons assess their combined contribution.

02

A safe move can still lead into a trap

Before step 13, both up and left are immediately safe. Handoff–Completion favors up while its continuation remains unresolved, and Handoff–Per-Step incorrectly predicts when the body will clear a later route cell. Both choose up and later collide. DynaJev’s incomplete guidance supports a left move that preserves an exit; its updated handoff at step 14 clarifies the detour, enabling safe passage at step 17.

The case illustrates how actionable partial guidance and subsequent updates can help when immediate safety does not determine future feasibility.

Direct access to the reasoning prefix

Snake-Hard without skills, with the same Feedback restart configuration. The Handoff + Prefix row reuses the no-skill DynaJev result.

Skills provide configuration-dependent gains

Refined skills improve several configurations while all model weights remain frozen. Their effects depend on the online configuration: some gains are substantial, while others are limited or negative. The skill toggle in Results shows both settings.

Task differences

Overcooked requires prerequisite chains across preparation, cooking, and delivery, so subgoal analysis can remain useful across several actions. Freeway keeps a persistent crossing goal while traffic gaps change. Plants vs. Zombies combines defensive planning with responses to arriving enemies. These task differences are consistent with different needs for reasoning continuity and replanning; PvZ results are compared within each difficulty because spawning frequency changes.

Across tasks, the relative value of continued reasoning and replanning depends on persistent subgoals and changing action conditions.
